# PR 1: the executable foundation

## Purpose

Establish a CLI contract and a repeatable path from TypeScript source to an
installed executable before introducing model behavior.

## The important concept: pure logic and effects

The operating system supplies strings in argv and observes output streams and
an exit code. `runCli` turns those strings into a result. The entrypoint handles
the process effects. Keeping this seam small makes behavior easy to understand
and test without mocking global process methods.

This applies single responsibility without creating a class for every noun.
The discriminated union models successful and invalid invocations explicitly.
Dependency injection can be as simple as passing the version as an argument.

## Acceptance criteria and evidence

- Help and version write to stdout and exit 0.
- No arguments shows help; unsupported or combined arguments use stderr and exit 2.
- The installed package reports its own manifest version.
- The packed artifact contains only the expected executable, implementation,
  metadata, license, and documentation.
- Type-checking, linting, formatting, tests, and packaging work without API keys.

Run `pnpm check` for executable acceptance evidence. Unit tests exercise behavior;
the package check installs the tarball outside the repository and invokes the bin.
CI repeats the checks on Linux and macOS with a frozen dependency lockfile.

Verified locally on macOS with Node.js 22.23.3 and pnpm 10.8.1:

- `pnpm check` passed, including nine unit tests and five installed CLI invocations.
- A separate clean, offline, frozen-lockfile install built successfully and the
  resulting executable reported version `0.1.0`.
- `pnpm dev --help` and `pnpm dev --version` worked from source.

Cloud CI has not run: the local repository has no GitHub remote configured.
No package has been published.

## Tradeoffs and risks

The parser supports only two flags. A parsing library would add little value
today; reassess when commands and options grow. Node 22 is the supported runtime
for this slice. Package publication remains disabled, and cloud CI results must
be checked after the branch is pushed.

## Exercise

```sh

node dist/cli/index.js --version

```

Then consider adding `--help --unknown`: should help suppress an invalid flag?
Our current contract rejects it. Find the test that preserves that decision.
Explain why checking only the returned text would miss a broken CLI contract.
