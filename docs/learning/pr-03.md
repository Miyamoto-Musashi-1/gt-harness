# PR 3. Streaming and cancellation

Streaming adds a second direction to the provider interface. The caller supplies
the prompt and a cancellation signal. The provider sends text chunks back through
`onText` while the request is still running, then returns its final outcome.
The CLI writes each chunk once and adds a trailing newline when necessary.

OpenAI uses server-sent events. Text deltas carry the new text, and a completion
event confirms the response finished. A connection can close after delivering
some text, so receiving text alone cannot establish success.
[OpenAI streaming guide](https://developers.openai.com/api/docs/guides/streaming-responses)

## Acceptance criteria

- `ask` prints text incrementally, preserving the final text and exit code 0 on success.
- Ctrl+C aborts the request, preserves already printed text, reports cancellation
  on stderr, and exits 130.
- A 60-second deadline covers both the request and reading the response stream.
- Incomplete responses, error events, and streams ending without completion exit 1.
- Stream cleanup runs on success, failure, and cancellation. The process removes
  its SIGINT listener after the command finishes.
- Deterministic tests exercise SSE parsing and cancellation. Installed-package
  tests check the real entrypoint with scripted text and an actual SIGINT.

Local validation passed with 27 unit tests, type-checking, linting, and the
installed-package checks. Those checks verify a completed stream and cancellation
of a stalled stream through the executable. Live model access requires API credentials.

## Ownership and cleanup

The entrypoint owns operating-system signals. An AbortController translates
SIGINT into a portable AbortSignal. The provider combines it with a deadline and
passes the resulting signal to the SDK. A finally block closes the stream.

The provider retains the completed text for callers that need a buffered result.
The output limit bounds this buffer. The terminal receives chunks during the
request. If failure follows partial output, consumers should use the exit code
to decide whether to accept that output.
