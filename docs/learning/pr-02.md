# PR 2. One prompt and one model answer

`ask` adds the first network effect. The CLI checks the arguments, then awaits a
function that takes the prompt and returns text or a user-facing error. The
entrypoint supplies the real provider. The CLI tests supply a scripted answer
through that same function interface.

The OpenAI adapter validates the API key and model ID, uses the SDK to send one
Responses API request, and reads the SDK's aggregated text. The adapter
translates errors before the CLI sees them, so terminal output can give actionable
guidance without dumping raw provider errors.
[OpenAI text generation guide](https://developers.openai.com/api/docs/guides/text)

## Acceptance criteria

- A single nonblank argument after `ask` reaches the provider unchanged.
- A completed text response goes to stdout with exit code 0. Malformed usage
  exits 2. Missing configuration or a failed model request exits 1.
- The request has a 60-second timeout, a 2,048-token output limit, retries
  disabled, and `store: false`.
- Offline tests cover the CLI and intercept the SDK's HTTP transport. The package
  smoke test installs the real runtime dependency and checks missing credentials
  through the installed binary.
